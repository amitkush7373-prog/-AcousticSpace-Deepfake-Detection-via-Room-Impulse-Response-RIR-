# AcousticSpace — Deepfake Audio Detection via Room Impulse Response (RIR) Analysis

An intern project for Infotact Solutions (Advanced Data Science & ML Engineering track).

## Problem Statement

Most deepfake audio detectors focus on vocal artifacts — robotic tones, unusual
inflections, biometric mismatches. Modern generative AI easily bypasses these
checks because it's optimized specifically to sound human.

**AcousticSpace takes a different approach: it doesn't listen to the voice, it
listens to the room.** Every recording — real or synthetic — implicitly claims
an acoustic environment. A voice generated by AI rarely has a physically
consistent Room Impulse Response (RIR): the way sound reflects, decays, and
reverberates in the claimed space. If the acoustic fingerprint of a clip
doesn't match the environment it claims to be recorded in, that's a signal
current biometric-only detectors miss entirely.

## Architecture

| Layer | Tech | Role |
|---|---|---|
| Audio processing | Python, Librosa | Extracts mel-spectrograms, MFCCs, and RIR features (RT60, DRR, C50) |
| Classifier (baseline) | PyTorch | Late-fusion CNN — spectrogram branch + RIR-feature branch |
| Classifier (advanced) | HuggingFace Transformers (AST) | Fine-tuned Audio Spectrogram Transformer, same late-fusion design |
| Breathing analysis | Librosa (onset/RMS/FFT) | Flags pauses with no breath signature, checks cadence vs. syllable rate |
| API | FastAPI | Serves `/api/analyze`, preloads models at startup for low-latency inference |
| Frontend | React + TypeScript + Vite | Upload, waveform (Wavesurfer.js), spectrogram heatmap, results, session history |
| Deployment | Docker, docker-compose, GitHub Actions | Containerized backend/frontend, CI pipeline on every push |

## How detection works, concretely

1. **RT60** — how long sound takes to decay in the space (bigger room = longer decay)
2. **DRR** — ratio of direct sound to reverberant sound (bigger room = lower ratio)
3. **C50** — speech clarity based on early vs. late energy (bigger room = lower clarity)
4. **Breathing cadence** — real speech has breath sounds roughly every 6–14
   syllables; many TTS/deepfake systems omit them or place them without
   regard to natural pacing

These features feed a late-fusion classifier alongside the raw mel-spectrogram,
so the model reasons about acoustic physics, not just spectral texture.

## Known limitations (honest notes)

- The classifier is currently trained on a small **synthetic** dataset
  (genuine vs. acoustically-mismatched clips generated with pyroomacoustics).
  Real-world accuracy depends on training with a real dataset — see below.
- RT60 estimation is a blind estimate from the recording itself (no clean
  reference impulse), so it's noisier than lab-grade RIR measurement.
- The AST model requires downloading pretrained weights from huggingface.co
  on first run — needs a machine with normal internet access.

## Setup

### Backend
```bash
cd backend
pip install -r requirements.txt
python -m app.dataset      # generates a small synthetic dataset for testing
python -m app.train         # trains the baseline CNN
uvicorn app.main:app --reload --port 8000
```

### Frontend
```bash
cd frontend
npm install
npm run dev                 # http://localhost:5173
```

### With Docker
```bash
docker compose up --build
```

## Using your own dataset

Drop labeled audio clips into:
```
backend/data/<your-dataset-name>/genuine/*.wav
backend/data/<your-dataset-name>/fake/*.wav
```
and point `DATA_DIR` in `app/train.py` (or `app/finetune_ast.py`) at that folder —
the feature extraction and training loop are dataset-agnostic.
